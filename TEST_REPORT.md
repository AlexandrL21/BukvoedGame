# Отчёт о тестировании и оптимизации «Буквоеда»

Дата проверки: 05.11.2026

## Результаты

- JavaScript: синтаксическая проверка `node --check` — пройдена.
- HTML: 67 уникальных ID, дубликатов нет.
- Связи JS → DOM: все 67 используемых ID присутствуют в HTML.
- Уровни: 20 из 20 прошли автоматическую проверку структуры и доступности поля.
- Проверено для каждого уровня: количество препятствий, отсутствие наложения на стартовую позицию, связность игровой области и достаточное количество достижимых клеток для букв.
- Проверена защита управления от ввода под открытыми модальными окнами.
- Добавлена автоматическая пауза при уходе вкладки в фон.
- Canvas адаптирован к размеру элемента и `devicePixelRatio`; DPR ограничен 2× для баланса чёткости и нагрузки.
- Декоративная перерисовка ограничена примерно 30 FPS, а в режиме сокращённых анимаций — примерно 8 FPS.
- Поиск по клеткам оптимизирован: вместо удаления первого элемента массива используется индекс очереди.
- Удалено лишнее пересоздание карты уровней при каждом изменении счётчиков.
- Обработчик изменения размера окна выполняется через `requestAnimationFrame`, чтобы не запускать серию тяжёлых перерисовок.
- Добавлены адаптивные правила для ширины 360 px и сенсорных устройств; минимальная высота сенсорных кнопок — 44 px.
- Прогресс и настройки хранятся через `localStorage`; ошибки доступа к хранилищу перехватываются и не ломают игру.

## Целевые форматы экранов

Интерфейс использует адаптивные точки 980, 720, 620, 430 и 360 px. Это покрывает типовые сценарии: настольный компьютер/ноутбук, планшет и смартфон. Canvas остаётся квадратным и масштабируется вместе с контейнером.

## Совместимость

Проект не использует серверные компоненты или сторонние библиотеки. Основа — HTML5, CSS, Canvas 2D, Web Audio API и стандартный JavaScript. Поэтому проект не зависит от конкретной настольной ОС и рассчитан на современные браузеры Windows, macOS, Linux, Android и iOS.

В текущей рабочей среде запуск Chromium по локальному адресу блокируется административной политикой (`ERR_BLOCKED_BY_ADMINISTRATOR`), поэтому полноценный автоматический визуальный прогон по нескольким viewport в этой среде выполнить невозможно. Финальную визуальную проверку рекомендуется проводить уже на опубликованной GitHub Pages-версии.
